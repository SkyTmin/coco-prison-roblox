# Где декомпилированному Java нельзя доверять буквально

19 октября 2026 года. Дополнение к [отчёту о декомпиляции](C:/Users/user/Documents/roblox-prison-research/client-audit/FULL-DECOMPILATION-REPORT.md).

Покрытие всех найденных классов исходным текстом подтверждено. Отсутствие явных заглушек «метод не декомпилирован» также подтверждено прежней проверкой. **Эти два результата не доказывают точность каждого выражения, возможность сборки и восстановление исходного авторского проекта.** При смысловом разборе обнаружены конкретные причины сверять текст с байткодом.

## 1. Вызов суперкласса выглядит как рекурсия

В [#PrcRb, строка 17](C:/Users/user/Documents/roblox-prison-research/client-audit/code-analysis/source/minecraft/01864.java:17) метод `etn()` вызывает `eto(this)`. В тексте `eto(#PrcRb)` на строке 26 затем стоит `var0.etn()`. Буквальное чтение создаёт впечатление бесконечного взаимного вызова.

В индексированном байткоде на `pc=1` у `eto(L#PrcRb;)V`:

| Поле | Значение |
| --- | --- |
| Opcode | 183, `INVOKESPECIAL` |
| Цель | `#QcTxC.etn()V` |
| Суперкласс #PrcRb | `#QcTxC` |

Это специальный вызов метода суперкласса, а не обычный виртуальный вызов `#PrcRb.etn`. Обычное выражение Java, выданное декомпилятором, потеряло существенное различие. Обфускатор размещает преобразованные методы в разных классах; название окружающего класса тоже нельзя автоматически принимать за назначение каждого статического метода.

Доказательство с точным дескриптором сохранено в `invokespecialCounterexample` файла [audit-validation.json](C:/Users/user/Documents/roblox-prison-research/client-audit/code-analysis/audit-validation.json). Это конкретный пример; он не является исчерпывающим списком всех таких случаев.

## 2. Потеря имён перечислений меняет смысл чтения

Например, [состояния дерева](C:/Users/user/Documents/roblox-prison-research/client-audit/code-analysis/source/addon-wada/00334.java:4) показаны полями `a`…`g`. Между тем парсер сравнивает `enum.name()` со строкой, полученной из JSON. Runtime-имена конструктора сохранены в байткоде и отличаются от имён полей:

`a=HIDDEN`, `b=LOCKED`, `c=EXCLUDED`, `d=AVAILABLE`, `e=AFFORDABLE`, `f=PARTIAL`, `g=MAXED`.

В такой форме видно, что `this == f || this == g` означает «частично или полностью изучен». Перекомпиляция обычного enum с буквенными именами поменяла бы поведение `name()` и чтения протокола.

[recover-enum-names.py](C:/Users/user/Documents/roblox-prison-research/client-audit/recover-enum-names.py) сопоставляет строковые константы, вызовы конструктора enum и запись в статическое поле без запуска класса. Общий результат — **2984 кандидата для 499 enum-классов** в [enum-aliases.json](C:/Users/user/Documents/roblox-prison-research/client-audit/code-analysis/enum-aliases.json). Это структурная эвристика, а не полноценная эмуляция стека JVM для каждого конструктора; в выводах о талантах отдельно проверены 16 соответствий трёх нужных enum.

## 3. Лямбды и захваченные аргументы

Восстановленный текст местами показывает ссылку вида `a::injectedLambda$...`, хотя явная сигнатура обёртки содержит дополнительные захваченные аргументы. Такая строка не всегда пригодна к обычной компиляции в показанном виде.

Для сопоставления обработчиков Wada использовались реальные цели bootstrap method handle и последующие вызовы обёртки, а не предположение по похожему имени. Все 620 регистраций имеют найденные целевые методы. Полное доказательство компилируемости каждого выражения лямбды этим не выполнено.

## 4. Предупреждение декомпилятора не равно отсутствующему методу

Общий поиск отметил 298 файлов с 331 совпадением широкой группы предупреждений. Туда попадают, например, несвёрнутые `switch` по enum и `ObjectMethods.bootstrap`. **Это не 298 доказанных сломанных файлов.**

В алгоритме пути талантов предупреждение `Unable to simplify switch on enum` оставило читаемые ветви. Смысл ветвей установлен через восстановленные значения enum и реальные обращения к полям, а не через имя обфусцированной буквы.

## 5. Что не возвращает декомпиляция

- Исходные имена локальных переменных и комментарии, если их нет в классе.
- Серверные конфигурации, базу данных и серверные методы, не доставленные клиенту.
- Java-тела native-методов. В основном клиенте индекс отмечает 9 native-объявлений; у них нет исследуемого Java-байткода. Их наличие не означает, что там найдены правила Prison.
- Подтверждение работы в текущем режиме: класс может присутствовать, но не активироваться сервером.
- Полную проверку типов и стека JVM либо эквивалентность игре по одному синтаксическому разбору инструкций.

## Как проверялись выводы этого разбора

Для чтения сохранены точные имена/дескрипторы методов, opcode/pc вызова, ссылки на поля, строковые константы, оригинальное имя файла в ZIP и безопасный путь распаковки. Существенные выводы закреплены исходными фрагментами и хешами.

Это существенно надёжнее буквального переноса Java-текста, но остаётся статическим анализом. Ни игровой байткод, ни чужие плагины в ходе исследования не запускались. Поведение клиента и сервера не проверялось игровыми тестами.
