# Аукцион: как устроен и почему без дюпов (27.10)

[владелец 27.10: «приступи к аукциону. Как будет работать между игроками, как товар туда кидать. Смотри баги, чтобы не было дюпов»]

## Что видит игрок

Окно «Аукцион» [Y] (и плитка в меню [X], и кнопка в меню телефона) повторяет оригинал [вики MENUS-SOCIAL «Аукцион /ah»].

Вкладка «Аукцион»:
- Фильтр типа: Все / Оружие / Броня / Инструменты / Зачарования / Прочее.
- Цена от–до, уровень от–до.
- Сортировка по времени / цене / уровню; повторный клик меняет порядок.
- Поиск по названию предмета или нику продавца.
- Сетка 10 × 6 со страницами.
- Подсказка лота — обычная подсказка предмета и под ней «Продавец», «Стоимость», «Истекает через 6д 23ч 59м».
- Клик по лоту спрашивает «Купить … за …$?».

Вкладка «Личные товары»:
- «Слоты: N / 5».
- Свои лоты с «Снять с продажи».
- Лоты, которые ещё выставляются, и покупки в обработке.
- Блок «Не поместилось в инвентарь» с кнопкой «Забрать».

«Продать»:
1. «Выберите предмет из инвентаря» — 36 слотов; деньги из кейса продать нельзя, они затемнены.
2. «Продажа предмета»: «Кол-во» (по умолчанию вся стопка) и «Цена за всё, $».
3. Строка «Комиссия 5 % — вы получите …».
4. «Выставить на продажу».

Числа (`scripts/design-decisions.json` → `auction`):
- срок лота 7 дней [вики];
- 5 слотов [вики];
- комиссия 5 % [вики];
- только деньги, цена от 1 до 100 млн $ целыми [решение];
- одно действие за 1,5 с [решение].

## Где что хранится

| Что | Где | Зачем |
|---|---|---|
| Лот (предмет, цена, продавец, статус) | DataStore `AuctionLots_v1`, ключ `lot_<id>` | Единственная правда о лоте. Статус active → sold / cancelled / expired (или `void` — надгробие). Любая смена — `UpdateAsync` одного ключа, поэтому двое покупателей на разных серверах не выиграют оба. |
| Витрина | MemoryStore `AuctionIndex_v1` | Копии активных лотов для просмотра, живут до конца лота. Сервер держит кэш на 10 с, фильтрует, сортирует и режет на страницы (`AuctionQuery`). Может отставать — покупка всегда проверяет сам лот. |
| Сторона игрока | Профиль, `p.auction` | `lots` — свои выставленные; `pendingSells` / `pendingBuys` — шаги, чей внешний результат ещё не подтверждён; `returns` — то, что не влезло. |

## Каждый шаг — по одной схеме (outbox)

1. Изменить профиль и записать шаг в профиль.
2. `ProfileService.SaveNow` — профиль на диске раньше, чем что-то изменится снаружи. Не сохранилось — откат, «попробуйте позже».
3. `UpdateAsync` на лоте.
4. Завершить шаг в профиле.

Если сервер упал или хранилище ответило ошибкой после шага 2, запись в профиле разбирается позже. Сервер перечитывает лот через `UpdateAsync`, который ничего не пишет: это никогда не кэшированный `GetAsync`. Предмет или деньги переходят ровно один раз, потому что запись и переход — одно изменение профиля.

Когда разбираются записи:
- при загрузке профиля;
- сразу после каждого шага;
- когда другой сервер сообщает о продаже (MessagingService `AuctionSold`);
- при открытии «Личных товаров»;
- раз в 5 минут.

- **Продажа.**
  1. Предмет уходит из слота, лот — в `pendingSells`, профиль сохраняется.
  2. Создание ключа, только если его нет.
  3. Лот переходит в `lots` и на витрину.
  - Если ответ не пришёл, сервер сразу перечитывает ключ:
    - лот есть — он выставлен;
    - лота нет — в тот же атомарный шаг пишется надгробие `void` (запоздалая запись уже не создаст лот), и предмет возвращается.
- **Покупка.**
  1. Деньги списываются, в `pendingBuys` записывается id покупки (`op`), профиль сохраняется.
  2. `UpdateAsync`: лот active, не истёк, та же цена, продавец ≠ покупатель → sold, `buyOp = op`.
  3. Исход:
     - выиграл — точная копия стопки с книгами и уровнем в инвентарь (не влезло — в «Забрать»), продавцу сигнал;
     - лот ушёл — деньги назад.
  - Если ответ потерялся, перечитывается `buyOp`: наш — предмет, чужой — деньги назад.
- **Снятие.** active → cancelled (только свой лот), затем разбор лота: предмет назад. Если лот уже продан — придут деньги.
- **Разбор своего лота** (`settleLot`). Пока лот лежит в `p.auction.lots`:
  - sold — +цена − 5 % (комиссия округляется вверх, в пользу дома);
  - cancelled / expired — предмет назад;
  - active, но время вышло — сначала становится expired.

## Чек-лист дюпов и защит

- [x] Профиль, который не загрузился (`IsReal = false`, никогда не сохраняется), не может ничего выставить или купить. Иначе предмет из пустого профиля стал бы настоящим.
- [x] Блокировка сессии профиля (`_lock` в записи, 300 с, запрос освобождения через MessagingService). Один профиль на двух серверах не живёт, кто украл блокировку — того кикает. Реализовано, на двух серверах ещё не проверялось.
- [x] Предмет уходит из инвентаря до внешней записи и до сохранения; бросить его на землю или переложить уже нельзя.
- [x] Деньги списываются до внешней записи; в той же правке проверка `coins ≥ price`.
- [x] Двойная покупка одного лота: атомарный `UpdateAsync` по статусу. Проверено: повторная покупка проданного лота — отказ без списания.
- [x] Потерянный ответ хранилища (запись прошла, ответ нет) — QA `fail lotAfter`. Покупка распознаёт свой `buyOp`, продажа видит свой лот. Проверено.
- [x] Ошибка до записи — QA `fail lot`. Покупка возвращает деньги («Аукцион не ответил — деньги вернулись»), продажа ставит надгробие и возвращает предмет. Проверено.
- [x] Профиль не сохранился перед шагом — QA `fail save`: полный откат. Проверено.
- [x] Повторная выплата продавцу невозможна: выплата и удаление лота из `p.auction.lots` — одно изменение профиля.
- [x] Одно действие игрока за раз (mutex) + 1,5 с между действиями + 0,3 с между запросами витрины.
- [x] Проверка типов всех аргументов remote: целые, NaN, диапазоны, id `[%w-]{1,64}`.
- [x] Свой лот купить нельзя; лот с другой ценой (старая витрина) — отказ.
- [x] Метаданные (книги, уровень, редкость, шанс) копируются глубоко: `InventoryService.add` теряет их у нештабелируемых, поэтому свой `put`.
- [x] Выставляемые лоты (`pendingSells`) занимают слот — нельзя обойти лимит 5, пока подтверждение висит.
- [x] Лот, истёкший пока продавец офлайн, возвращается при входе; витрина не показывает истёкшие, покупка истёкшего — отказ.
- [ ] Нагрузка: витрина читается целиком (до 10 000 лотов, 50 запросов по 200) раз в 10 с, пока кто-то смотрит. Хватит на старт; при росте — ключи по категориям.
