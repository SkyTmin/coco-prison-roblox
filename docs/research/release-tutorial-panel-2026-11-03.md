# Compact tutorial task panel

Latest owner request, 2026-11-03: move the tutorial task card to the LEFT and match the upgrade requirements presentation, with individual resource icons, names, exact counts, completion ticks, and a separate money row. Only completed requirements should be green. Also stop sending a new player to the buyer after every mined block.

## Changes

- `src/client/TutorialPanel.luau` is a presentation-only renderer. The normal card is 250 px wide, with dark resource rows, a localized requirements header and completed/total count. Incomplete counts are neutral light text; completed counts turn green with a tick. Summary and actual money use the same rule, including reused rows after a stage change/reset. Its icons use `Config.counterIcon`, the same helper as UpgradeWindow; this resolves the genuine gravel, dirt and sand assets through `Config.iconFor`. No asset or requirement was invented.
- The goal title, exact required counts and money come directly from the shared Tutorial goal. Actual spendable money stays separate from the explicitly labeled projected amount after selling. The level-up task uses the same renderer with its real total-block requirement. Reused rows reset their dimensions when the task changes or progression is reset.
- Placement prefers the left edge. It considers visible buttons, the actual Scoreboard and hotbar rectangles, the movable jump proxy, and Roblox's native jump/joystick areas. It tries a clear adjacent column when necessary. A short available region scrolls the card's contents at readable text sizes; it never overlays controls as a fallback. Menu shortcuts retain a 44 px touch target. The only unrelated-looking client entry-point change is the stable `Scoreboard` name used to recognize that existing HUD panel.
- `TutorialGuide` keeps the beam, control highlights, input observation and persisted step semantics. It now considers ALL unfinished materials, camera direction and real visibility, with a preference for nearby upper surfaces. Turning/walking can replace an intact target. Both phases select the buyer only when the shared goal says `saleReady`; the first shovel sale is offered once all resource requirements are met, even if it cannot yet pay the entire price. Subsequent trips wait until the remaining amount can be covered. Upgrade guidance still requires actual money. The shared quote and server SellAll use the same `Selling.quote` calculation.
- New compact labels and projected-sale instructions are present in Russian, English, Spanish and French in `Strings/ReleaseTutorial.luau`.
