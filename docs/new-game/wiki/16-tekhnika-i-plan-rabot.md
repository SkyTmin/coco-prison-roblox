Источник — `studio/06` (технический архитектор), урезано под состав запуска ([15](15-zapusk-i-obnovleniya.md)) и правки критика

[✅ владелец, CLAUDE.md 10.11]. Новый репозиторий и новый experience; старая игра остаётся работать [✅ владелец, PLAN].
Числа без источника — [решение 06].

## 1. Архитектура коротко

**Простыми словами.** Шахта — это формула, а не склад кубов: что лежит в любом слое, вычисляется из номера слоя и «зерна»
шахты. Хранятся только выбитые места. Телефон шлёт «я ударил сюда», сервер всё проверяет и считает, телефон красиво рисует.
Кубы есть только на телефоне и только видимые.

| Решение | Суть |
|---|---|
| **Хранение пустот** | для каждой «дорожки» (x, y вглубь) — вершина `top` + отсортированный список отрезков «пусто от a до b»; передний слой `front = min(top)` — правило «передний слой не пуст — не едем» и проезд пустых слоёв одним движением выполняются сами |
| **Руда — квотами** | дорожка режется на куски по 50 слоёв; для куска формула решает «сколько какой руды», затем «где» (по гладкому шуму — жилы и скопления). Подсчёт 75 000 выбитых блоков ≈ 1 500 сложений, точно |
| **Длина мира — из конфига** | не константа `STRATUM_LEN = 100` (правка 07, строка 1); **длины миров кратны 50**, чтобы куски не пересекали границу |
| **Прочность и Плита** | урон обычных блоков — только в окне, не сохраняется; **урон Плиты-стража хранится в профиле** (правка 07, строка 3); Плита останавливает любые прогоны вглубь |
| **Зерно** | своё у игрока, новое при перерождении, только на сервере; клиент получает только состав окна 20 слоёв (не «просветить» читом) |
| **Лимит дыр** | ≤ 4 000 отрезков; глубже окна способности режут только «прогонами» (целый отрезок дорожки или целые слои); при превышении сервер дорезает мелкие дыры до целых слоёв **в пользу игрока** |
| **Стена** | на запуске до 9×3 (07, строка 55); формат координат расширяемый (`x` от центра, новые дорожки получают `top = front`) |
| **Награда** | `rangeHist` → монеты, статистика, задания; ключи — накопитель; находки — особые клетки, берутся один раз |
| **Сохранение** | `p.mine = { v, seed, w, h, front, top, holes }`, top/holes — base64 от varint; обычно < 2 КБ, максимум ~20 КБ; `decode` проверяет инварианты, битое → `loadFailed`, профиль не сохраняется; автосохранение 120 с, сессионный замок `_lock` |

### 1.1. Протокол

| Направление | Сообщение | Суть |
|---|---|---|
| клиент → сервер (`MineIntent`, `buffer`) | `Hit(seq, x, y, dRel)`, `Ability(...)`, `Resync` | только намерения; ≤ темпа кирки |
| сервер → хозяин (`MineResult`) | seq, front, удалённые клетки окна (с поколением каскада), прогоны глубже окна, сценарий эффектов (путь молнии, центр взрыва), монеты, логические блоки, находки, при сдвиге — новые слои окна | обычный удар 20–60 байт, каскад ≈ 0,5 КБ |
| сервер → все (`MineFx`, Unreliable, пачкой раз в 0,1 с, ≤ 800 байт) | `plot, kind, x, y, size` | только для вспышки ульты соседа над воротами; **упрощённую стену соседа не делаем** (07, строка 43) |

**Проверки на сервере:** ведро токенов под темп кирки; тип и диапазон; клетка в стене и в окне; клетка цела и **видна**
(на фасаде или с пустым соседом); игрок на своей площадке; разбор удара с бюджетом каскада (≤ 3 поколений, ≤ 400 клеток, ≤ 8
прогонов); выдача через `ProfileService.Mutate`; ошибки молча отвергаются (`reject(seq)`), без киков.

**Предсказание:** клиент в тот же кадр показывает трещину, звук и удаление **базовой формы**; ответ сервера через 100–200 мс
заменяет предсказание и добавляет фишки; несовпадение seq → `Resync`. Во время езды стены удары разрешены.

### 1.2. Телефоны

| Цель [решение 06] | Значение |
|---|---|
| кадры | 60 FPS на среднем телефоне, ≥ 30 на слабом (1 бюджетный Android + 1 старый iPhone — модели называет владелец) |
| draw calls в шахте | ≤ 300; деталей шахты на экране ≤ 600 |
| сервер | удар ≤ 1 мс в среднем, ульта ≤ 15 мс (иначе по кадрам) |
| текстуры | ≤ 40 МБ |

Блоки — пул ≤ 1 000 закреплённых деталей, рисуем только клетки с открытой гранью; один `MeshPart`-куб с UV и текстурой руды
(не Decal на 6 граней); MaterialVariant — только после проверки, что не «плывёт» при езде. Езда — `BulkMoveTo` окна;
тоннель — 8–16 модулей по кругу. Бюджет эффектов — таблица [11 §5](11-effekty-animacii.md#5-бюджет-эффектов-канон-и-инструменты)
(канон), замер подтверждает. Огромные аватары R15 — прозрачность у камеры/ограничение размера в шахте.

### 1.4. Конфиги и симулятор

- `design-decisions.json` — разделы `mine`, `ores`, **`worlds`** (вместо `strata`: длина, руда и доли, цена, прочность,
  особые блоки, музыка, цвет), `starterPickaxes`, `families`, `rarities`, `pickaxes`, `levelCost`, `cards`, `cascade`, `rush`,
  `events`, `drops`, `multipliers` (потолок временных ×10), `rebirth`, `boosters`, `cases`, `donate`. Сгенерированные
  `Config/*.json` руками не правим.
- **Проверки, которые роняют сборку:** Σ долей руды мира = 1; длина каждого мира кратна 50; у кирки семья и редкость
  существуют; у каждого `id` строки во всех 4 языках; цены монотонны; шансы ≤ 1 на максимуме; `maxGen ≤ 3`.
- **Симулятор** `scripts/sim/economy.luau` через Lune `require`-ит настоящие `MineGen`, `MineState`, `Resolve`, `Procs`,
  `Economy` — цифры не разъедутся с игрой. Модели игрока: «тапер», «авто», «редко заходит»; 200 прогонов Монте-Карло; отчёт
  markdown + CSV в `docs/new-game/sim/`; флаги — [13 §8](13-ekonomika.md#8-цели-для-симуляции). Запускать после любой правки
  баланса; час игры × 200 прогонов < 1 мин.
